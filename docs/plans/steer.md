## Goal
From the admin dashboard an operator picks a playlist and/or types one line of direction, chooses once / 15-120 min / until the next show, and from the next pick on the station plays only that playlist (no repeats until exhausted, then loops) and/or leans its picks and talk the way the line says, with a banner showing what is active and when it ends.

## Changes
Decisions (numbered as asked):
1. Storage: new top-level settings key `steer: Steer | null`, persisted in settings.json like every non-schedule key (E14) — survives restart, lazily expired by `activeSteer(now)`, swept by the existing janitor. Shape `{ playlistId: string|null, prompt: string, once: boolean, startedAt, expiresAt }`; `expiresAt` is always a number (`once` → `startedAt + STEER_MIN_MINUTES*60_000`, i.e. 15 min: a once-steer the station cannot consume — hard budget, a queue kept full by requests — must not fire hours later) so the schedule rules apply verbatim (E12). `once` is consumed at E16 after a successful push. `until: 'schedule-change'` is spent in the route via `resolveTakeoverWindowNow(startedAt)` (E13) and never stored.
2. A sibling object, not a `ScheduleOverride` extension: a takeover changes show identity (session roll, persona, programme — E1), a steer must not. Mutual exclusion lives in the ROUTES, the layer that already owns "clear a takeover = update + booth line + session roll" (E13); `settings.update()` stays a validator.
3. Prompt text enters at three seams, each a labelled block, never the agent's system prompt (cache, E6/E7): agent → `promptSuffix` on the pick event turn; pool → one block in `pickerSystem()` (stateless one-shot, E8); talk → one ungated line in `buildContextLines()` read off `context.steer`, which `getFullContext()` sets (E9: the prompt module stays settings-free). One wording, `steerClause(text)`: `Operator steer — trusted direction from the station operator, NOT a listener message (E10); while it runs it outranks the show brief and its music filters. Never mention the operator, this direction or that the music was changed on air or in your pick reason: "<text>"` (the reason is public, E7). Show `topic` stays in the prompts; the clause says who wins. A prompt-only steer leaves the show object untouched (no overlay, no synthetic shape); a playlist steer changes `pickSystem()`'s shape at its start and end — two cache misses per steer, by design, the same as a show change.
4. Playlist mode = the show playlist-anchor machinery with a fixed overlay: `steeredShow(show, steer)` returns the resolved show with `playlistIds: [steer.playlistId], playlistStrict: true, playlistExhaust: true, playlistInOrder: false, excludedPlaylistIds: [], moods/genres/eras/energies: [], vocals: '', filtersStrict: false` (E2), or a music-only synthetic shape (`id: null, name: 'Steer', topic: '', persona: null, guests: [], caps null`) when no show is on air. FIVE pick-path readers switch: the four show reads (E3 ×2, E4, E6) and the artist-episode source (`showPreparation.read(…).music` at dj-agent.ts:181 and picker.ts:637 → `null` under a playlist steer), because E5 lets an episode outrank the anchor on both paths. Identity readers keep `resolveActiveShow`. Exhaust+loop then holds on both paths through E5 unchanged. Clock: the steer is judged at the pick's LOOK-AHEAD instant like the takeover (E1/E3) — `resolvePickShow(date) = steeredShow(resolveActiveShow(date), activeSteer(date.getTime()))`, pool path passes `new Date(ctx.at)` (E4); since `startedAt ≤ now ≤ showAt`, "takes effect at the next pick" still holds, and an "until the next show" steer cannot leak a track past its end. What "no repeats until exhausted" means (E5): the memory is the station-wide play sidecar, so steered-playlist tracks aired recently are withheld on the first lap (resume-safe across a restart); after one lap the longest-waited track repeats (the loop); a playlist of ≤ 2 tracks gets window 0 and loops freely — `POST /steer` warns below 3. An in-order show resumes its saved cursor after the steer and may replay what the steer aired (E24).
5. Listener requests bypass the picker (E16) → played as today. Scheduled segments keep firing; the talk line is a lean the model reads (E9), not a gate.
6. Every steer opens with a fixed list. Preview = one pool-picker call under the proposed steer (`count: 5`), no agent run: bounded to one `djObject` call over a ≤24-track re-sampled pool (E8/E17); `diagnoseShowCandidates` only counts (E17) so it cannot supply tracks; its `warnings` ride along. The Preview button fills a server memo keyed on `playlistId + prompt` (5 min; the pool is a per-call sample, E8, so age does not make a plan worse). **Start always plays the first five in advance** (operator decision): `POST /steer` uses the memo when one matches, else makes that same single call itself; either way it returns the tracks (`tracks`) so the card shows them, queues them in order, and consumes the memo. No `fromPreview` flag. The tracks go through `enqueuePick` (E16/E28) — `aiPicked: true, requestedBy: null`, exactly an ordinary pick's shape — so to listeners they are indistinguishable from picks (E26: `requestedBy`/`source`/`block` ARE rendered by the skins, hence not used). No model call is made per queued track; no pick runs while they are queued (E27); steered picking resumes when they run out. Impossible cases, decided: (a) hard token budget (`budget.picksAllowed()` false, E11) → 409 "daily token cap reached — picks are paused, so the steer could not work out its opening list"; the steer is NOT started, because with no picks running it would do nothing anyway. (b) model failure or a malformed object → 502, steer NOT started (the list is computed BEFORE `settings.update({ steer })`, so a failed Start leaves no half-state); the card toasts it and leaves the form filled for a retry — recommended over a listless start, which would contradict the sentence the card just showed. (c) fewer than five eligible → queue what there is (1-4) and say so; zero eligible (empty pool, every candidate recent/blocked) → 409 "nothing eligible under this steer". (d) `once` → the same call with `count: 1`: one model call, one track, and the S4 consumption in `enqueuePick` clears the steer on that push — "once" still needs a call, since choosing the track is the pick. Previewed/opening tracks cost one pool-picker call in total instead of one pick each. Pre-Start sentence (pure `startSentence()`): preview valid → "Start plays these N tracks first. No model call is needed for them; picking continues after."; none → "Start works out the first five tracks with one model call, shows them here and plays them; picking continues after."; stale (inputs changed or >5 min) → "These tracks are out of date; Start will work out a new list." Private marker: a new `QueueItem.steer?: string` (`startedAt` as a string key), set through `enqueuePick`'s option bag → `push`; `mapItem` is an explicit allowlist (E26), so `/state`, `/session` and `/now-playing` never carry it, and `persist()` keeps it across a restart (E26). Clear, expiry (janitor) and a takeover replacing the steer call `queue.removeSteerQueued(key)` (the `removeUpcomingBlock` loop generalised over a predicate, E26 :4132-4148) so un-aired steer tracks go with it; an already-sent one plays out. The OPERATOR still sees the marker: `GET /steer` returns `queued: [{ id, title, artist, sent }]` from `upcoming.filter(i => i.steer === key)`, and the dashboard queue table badges rows whose `subsonic_id` is in that set (same `dashKeys.steer()` query the card holds). Interactions: queued items are appended to the tail (E26 :1018), so a listener request arriving meanwhile plays after the opening run; between the opening tracks no host links air (links ride pick cycles only, E27) while idents/hourly/segments still fire; as ordinary picks they are subject to the length cap and the show-boundary cut like any pick; they count toward exhaust/no-repeat when they end (E27 :3411-3432) and are excluded from the next pick while queued (`queuedIds`). `startNow`: push the opening tracks FIRST, then `dropQueuedPicks` — its re-pick kick sees a non-empty queue and stays quiet (E19 gate). A track already upcoming / on air or refused by `push` (`-1`/`-2`) is skipped and counted (`skipped`); a track Liquidsoap later fails to resolve takes the existing `onPushResolveFailed` path (E19 :3935-3948).
7. Introduce = one host LINK before the first opening track, not an announcement (replaces "announce"): `introduce: true` (card switch, off by default) → `generatePickLink` (E28) with `previous` = the queue tail or the on-air track, `current` = the first opening track, the usual `context`/`recap`/`recentTracks`/`recentOpeners`/`lastLink`, plus a new `steerRun: [{ title, artist }]` of the following opening tracks (≤4) which `linkPrompt` renders as one section — "Coming up right after this one, in this order: … — you may mention one or two of them by artist; never say the music was chosen for you or by anyone."
