# Rework authentication: accounts, cookie sessions, OIDC, one station lock
Status: approved
Issue: diblaze/subwave#3 (supersedes #1; upstream PRs target perminder-klair/subwave `develop`)
## Goal
On a private station every listener route, image and stream mount refuses a caller with no credential and admits an admin session, an account/OIDC session, an API token or the shared stream password — each checked through one resolver with a strike path — while every credential that works today (env Basic, `x-station-auth`/Bearer/`?auth=`, Icecast Basic) keeps working after upgrade with no operator action.

## Changes
Design first (settles the issue's seven points), then slices. Nothing below adds a role beyond `admin` and `listener`: 229 `requireAdmin` sites (rg over `controller/src/routes`) and one gate are all the code distinguishes; "operator/DJ" is YAGNI.

**Identity model.** `STATE_ROOT/auth.json`, mode 0600, written with `writeFileAtomic` (E20), install-level like `icecast-secrets.env` (E19: add to `INSTALL_LEVEL`, `duplicateAction` → `skip`), outside backups (E18) and station switches — the E21 property kept: deleting the file returns to env-only. Not settings.json (per-station, in backups), not library.db (E23). Shape: `{ version: 1, envCredentials: true, users: [{ id, username, role, passwordHash | oidc: { issuer, sub }, disabled }], tokens: [{ id, name, role: 'admin', sha256, createdAt, lastUsedAt }], sessions: [{ sha256, userId | null, role, expiresAt, via }], oidc?: { issuer, clientId, clientSecret, scopes, adminGroups, allowListeners } }`. Password hash: `crypto.scrypt` N=2^15 r=8 p=1, `scrypt$N$r$p$salt$dk` base64url, `timingSafeEqual` (E22); the same helper hashes the station password. API tokens `swt_` + 32 random bytes, stored as sha256, shown once, role admin only (a listener machine credential is the station password; YAGNI).

**Resolver.** New `controller/src/middleware/authn.ts` `resolveAuth(req) → { role: 'admin'|'listener'|null, via }`, tried in order: session cookie → `Bearer swt_…` token → `Basic` (env creds, then local account) → station password (`x-station-auth`, plain `Bearer`, `?auth=`, E6) → stream token `sst_…` in the same carriers. One rule: a credential that was PRESENTED and failed strikes its own surface — admin-class (Basic, `swt_`) through `authStrikes` (E2), station-class through `checkAuthRateLimit(ip,'station-read')` (E4) — and a request that presented nothing never strikes (E2:143, fixes E5). scrypt runs once per distinct candidate: verified `(hashId, sha256(candidate))` pairs sit in a `util/ttl-cache.ts` entry for 10 min, dropped on password change, so a poller sending the password per request costs a sha256, not a scrypt. `requireAdmin`/`requireAdminUi` become `role === 'admin'` over the resolver (E2's open mode stays: `!ADMIN_AUTH_REQUIRED && users.length === 0` passes, logs the existing warning; production refuses to boot without env creds OR one admin account). `requireStationAuth`: lock off → `next()`; `role` admin or listener → `next()`; else `Cache-Control: private, no-store` + 401 with `privacy` booleans (E11) — never derives admin from an open gate, so a dev console with no credential on a private station is a listener and types the password (stated limit; E7 fail directions untouched).

**Sessions.** `POST /auth/login { username, password }` (env creds accepted as `userId: null, via: 'env'`), `POST /auth/logout`, `GET /auth/me`. Cookie `subwave_session=<32 random bytes b64url>`; server stores sha256; `HttpOnly; Path=/; SameSite=Lax; Max-Age=30d` sliding; `Secure` by E3's rule. Lax, not Strict: the OIDC callback is a cross-site top-level navigation and must carry the pending-flow cookie. No signing key: lookup, so logout = delete row, restart-safe (persisted for admin/account sessions; shared-password listener sessions live in a `BoundedKeyMap` only — lost on restart, and E30's re-verify-on-mount re-mints them). CSRF: a cookie-authenticated request with method outside GET/HEAD/OPTIONS must carry an `Origin` (or `Referer`) whose host equals the request `Host` (E11 `publicOrigin` idiom) else 403; Basic/Bearer requests skip it (no ambient authority). Covers the five multipart routers (beds, dj, jingles, sfx, voices import `audioUpload`/`zipUpload`). Web: `adminAuth.ts` (E26) posts to `/auth/login`, stores nothing, `adminFetch` adds `credentials: 'include'`; the 401-publishes-sign-out store is unchanged. Cross-origin (E31): `cors.ts` echoes `Origin` with `Access-Control-Allow-Credentials: true` when the Origin's hostname equals the request Host's hostname (same-site split-port dev), otherwise today's `*` without credentials; a cross-origin web on a different host keeps the Basic fallback (`adminFetch` falls back to Basic only when `/auth/login` answered but `/auth/me` then 401s — the "cookie did not stick" signal) and the password-in-localStorage listener path, both unchanged. Server-side `/dj` (E33) stays credential-less.

**Station lock semantics.** `stationLockEngaged` (E6) stays the rule. Admitted: admin role (any `via`), listener role (session from `/station-auth`, OIDC/local listener), the shared password, a live stream token. `POST /station-auth` success additionally sets the listener session cookie, so the web player sends the password once per visit, not per poll. Images: `/cover/:id` and `/persona-avatar/:id` gain `requireStationAuth`; same-origin `<img>`/MediaSession/skins (E34) ride the Lax cookie; a URL-only client appends `?auth=<password|sst_…>`; `Cache-Control` becomes `private, max-age=…` only while the lock is engaged (E10 unchanged on a public station). Stream: `GET /auth/stream-token` (any session) → `{ token: 'sst_…', expiresAt }`, 24 h, in-memory TTL map sha256 → `{ sessionSha, exp }`; `listenerAuthDecision` (E6) tries `sst_` lookup on `pass` or `mountAuthToken(mount)` before the password compare; revoked when its session is deleted; expiry never cuts a live connection (E14). `withStreamAuth` (E29) prefers a cached token and the 5 s poll refreshes it under 1 h left, so a reconnect always has a live one; the native app keeps `?auth=<password>` (E36).

**OIDC.** Authorization code + PKCE + discovery via `openid-client` (new dep; E22 — nothing in tree speaks discovery/JWKS; it wraps `oauth4webapi` + `jose`, the smallest maintained pair; Unverified: v6 API names). Routes in the controller (sessions live there): `GET /auth/oidc/start` → sets `subwave_oidc` (random id → in-memory `{ state, nonce, verifier, returnTo }`, 10 min, Lax) → redirect; `GET /auth/oidc/callback` → exchange, verify `nonce`, upsert `users[{oidc:{issuer,sub}}]`, role `admin` if `groups` ∩ `adminGroups` else `listener` if `allowListeners` else 403 → session cookie → redirect to `/admin` or `/`. Redirect URI `${SITE_URL}/api/auth/oidc/callback` (E46; `SITE_URL` already required). Config in `auth.json.oidc`, edited at `GET/POST /auth/config` (admin, `clientSecret` redacted `'set'` like E15). IdP down or misconfigured: `/admin` sign-in shows the local form beside the "Sign in with …" button; env creds and local admins always work (break-glass, E21). Logout = local only. Forward-auth headers (`Remote-User`/`Remote-Groups`) are a trap, not a first slice: the controller is reachable off the proxy (compose network, dev `:7701`, byo topologies E46), E4 already documents header trust as a one-header bypass, and a safe version needs a trusted-proxy allowlist plus a shared secret — more config than the OIDC client and weaker. Deferred.

**Compatibility on upgrade (zero operator action).** Env Basic: still verified by the resolver on every route (CLI E38, MCP E37, health-check, old browser tabs with E26 localStorage). Station password: same three carriers (E6) plus the `/listener-auth` Icecast Basic/`?auth=` path (E13/E14). Web: a client shipped before the controller sends `Bearer <password>` (preflight-safe on old controllers, E8). Native 1.5.0: unchanged on public stations; on a private station after slice 2 it shows an empty player with audio playing (E36) — announced in the slice-2 release note (operator decision 2026-10-10 in `station-password-coverage.md`); the app slice is separate and untestable here.

**Threat model.**

| Credential | At rest | Guessable via | Limit |
|---|---|---|---|
| env `ADMIN_PASS` | `.env` plaintext (unchanged, E21) | Basic on any route | `authStrikes` 10/15 min per device-or-ip (E2); station-gated routes route Basic through the same path (E42) |
| local account password | `auth.json` scrypt | `POST /auth/login`, Basic | same `authStrikes`; login also 429s on a full address bucket |
| API token `swt_` | `auth.json` sha256 | Bearer | 256-bit random; a wrong `swt_` strikes `authStrikes` |
| session cookie | sha256 in memory/`auth.json` | cookie only | 256-bit; HttpOnly; Lax + origin check (CSRF); logout revokes |
| station password | `settings.json` scrypt (slice 3) | `/station-auth`, `x-station-auth`/Bearer/`?auth=`, `/listener-auth` (`pass`) | 20/15 min per (surface, ip) (E4/E5, presented-only); `/listener-auth` edge-denied + forwarded-header 404 + failure delay (E12) |
| stream token `sst_` | sha256 in memory | `?auth=`, Icecast `pass` | 256-bit, 24 h, dies with its session; appears in Icecast access logs like the password does today (E14) |
| OIDC client secret | `auth.json` 0600 | never compared by us | IdP-side |
| OIDC flow (`state`/`nonce`/PKCE) | in-memory, 10 min | callback forgery | nonce bound to the pending cookie; code exchange is server-side |

Residual (unchanged): `clientIp` trusts `xff[0]` behind a misconfigured edge (E4) — per-address limits are defence in depth, durable enforcement is the edge's, as ratelimit.ts:1-3 already says.
